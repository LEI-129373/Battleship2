# Tarefa 2B — Checkstyle (123282)

**Aluno:** 123282 — Cíntia Brandão

## Regra escolhida

- **Categoria:** Nomes de classes e interfaces Java
- **Regra Checkstyle:** `TypeName`
- **Ficheiro de configuração:** `checkstyle-123282.xml`
- **Workflow:** `.github/workflows/checkstyle-123282.yaml`

A regra aplica-se aos nomes de classes, interfaces, enums e records. Exige que estejam em PascalCase, ou seja, que comecem por uma letra maiúscula, seguida apenas de letras e dígitos, sem `_`, segundo o padrão `^[A-Z][a-zA-Z0-9]*$`.

## Demonstração da violação

Foi criada a classe `Test_1` no ficheiro `src/main/java/battleship/Test_1.java`:

```java
public class Test_1 {
```

O Checkstyle detetou a violação na linha 3, porque o nome da classe continha `_`, o que não respeita a convenção PascalCase.

- **Execução vermelha:** https://github.com/LEI-129373/Battleship2/actions/runs/42523381101
- **Execução verde após correção:** https://github.com/LEI-129373/Battleship2/actions/runs/42527445592
- **Pull Request:** https://github.com/LEI-129373/Battleship2/pull/23

A correção consistiu em alterar o nome da classe `Test_1` para `Test1`.

## Limitações da regra

A regra `TypeName` verifica apenas se os nomes dos tipos respeitam o padrão definido, sem avaliar se são claros ou descritivos. Por exemplo, classes chamadas `Test1`, `Aux` ou `ClasseA` passam na verificação, apesar de o nome não explicar a responsabilidade da classe. Além disso, a regra não deteta nomes enganadores, como uma classe `Fleet` que na verdade representa um único navio, nem verifica se o nome da classe é coerente com o resto do domínio do projeto. Assim, o Checkstyle ajuda a garantir consistência na nomenclatura, mas não substitui a revisão humana do código.
